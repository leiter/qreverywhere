## 1. Export compliance

| Question | Answer |
|---|---|
| Does your app use encryption? | **No** |
| Declared in binary | `ITSAppUsesNonExemptEncryption = false` in `iosApp/iosApp/Info.plist` |

The app contains no cryptography and makes no network connections at all — there is no HTTP client
anywhere in the codebase. Because the key is in the Info.plist, App Store Connect will stop asking
this per build.

> Note: "Cryptocurrency" QR codes are not encryption. The feature only writes a wallet address the
> user typed into a QR image.

## 2. App Privacy ("Data Collection")

**Answer: "No, we do not collect data from this app."**

This is the whole questionnaire — selecting "No data collected" ends it. It is accurate:

- No analytics, crash-reporting, ads, or tracking SDK is linked.

## Open items — these still need you

1. **App Review phone number.** I did not invent one. Add it in App Store Connect, or create
   `iosApp/fastlane/metadata/review_information/phone_number.txt` so `deliver` uploads it.
2. **Version number mismatch.** `iosApp/iosApp/Info.plist` ships `1.1` / build `10`, but
   `project.pbxproj` says `MARKETING_VERSION = 1.1.0` and `CURRENT_PROJECT_VERSION = 8`. Because
   the target uses `INFOPLIST_FILE`, the **Info.plist values are what ship** and the build settings
   are dead — which also means fastlane's `increment_build_number` silently changes nothing. Decide
   on one source of truth. Also consider whether a first-ever release should be called 1.1 rather
   than 1.0.
3. **Screenshots.** Not resolved — details below.
4. **Copyright name.** I used "2026 Marco Leiter"; it must match the legal entity on the developer
   account.

## Screenshots — current state

App Store Connect requires, at minimum, iPhone **6.9"** (1320×2868) and, if you ship for iPad,
iPad **13"** (2064×2752).

| File set | State |
|---|---|
| `6.9_*.png` (1320×2868) | **Kept.** Correct 6.9" size. Renamed from the misleading `6.7_` prefix. Still a content problem: `01_scan` shows **"Camera not available — Running on simulator"**, a poor first impression that invites reviewer questions. Needs a real-device recapture. |
| `iPhone 67_*.png` | **Deleted.** Duplicates with a filename `deliver` cannot map to a device. |
| `12.9_*.png` (1668×2420) | **Deleted.** 1668×2420 is iPad Pro **11"**, not an accepted App Store screenshot size, and the `12.9_` prefix would have made `deliver` upload it as a 13" asset. Would have been rejected. |

Consequence: there are currently **no iPad screenshots**. Either capture an iPad 13" set (2064×2752)
or set the app to iPhone-only in App Store Connect before submitting.

Automated capture was attempted and is blocked: macOS denies Apple Events to the Simulator
(error −1743), the `qreverywhere://` deep links raise a confirmation dialog that itself needs a tap,
there is **no UI-test target in `iosApp.xcodeproj`** (`iosAppUITests/ScreenshotTests.swift` is
orphaned), and maestro is not installed. Any one of the following unblocks it:

- Grant Automation permission (System Settings → Privacy & Security → Automation).
- `brew install maestro` — flows already exist in `iosApp/screenshots/*.yaml`.
- Add the UI-test target so `ScreenshotTests.swift` actually runs.
- Capture on a physical device — the only way to get a real camera view in the scan screenshot.

## Evidence

Claims in the store description were checked against the code before being written:

- All 12 creation types exist: `feature/create/.../CreateScreen.kt` plus `Create{Text,Email,Vcard,
  WiFi,Calendar,Location,MeCard,AppStoreLink,Payment,Crypto}Screen.kt`.
- History search: `feature/history/.../HistoryViewModel.kt`.
- On-device URL safety warnings: `core/base/.../usecase/UrlSafetyChecker.kt` (local heuristics only)
  and `UrlWarningDialog.kt`.
- Home screen widget: `iosApp/QrWidget/`.
- 25 in-app languages: 24 `values-*` locale folders plus the base in
  `core/base/src/commonMain/composeResources/`. Only 22 of these exist as App Store localizations —
  Bengali, Filipino, and Swahili are not App Store Connect locales, which is why the store metadata
  covers 22 while the app itself covers 25.
- No network: no `HttpClient`, `URLSession`, `ktor`, or `okhttp` reference anywhere in the app code.
